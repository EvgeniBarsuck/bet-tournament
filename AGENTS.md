# Работа с репозиторием

NestJS-сервис: HTTP и RabbitMQ consumer в одном процессе, PostgreSQL — источник истины. Node.js 24+, TypeScript strict, npm. Задание и запуск описаны в README.md, принятые допущения — в DECISIONS.md.

## Структура

- `src/bets/` — схема события (Zod), `BetsService` (правила начисления и отмены, границы транзакций), `BetsRepository` (весь SQL по ставкам и счетам), `BetsConsumer` (разбор сообщения, ACK/NACK).
- `src/leaderboard/` — SQL-запрос рейтинга и HTTP-контроллер.
- `src/db/` — пул `pg`, `transaction()`, `retry.ts` (классификация временных ошибок и повтор целой транзакции), раннер миграций.
- `src/messaging/topology.ts` — очередь, DLX и DLQ.
- `migrations/` — SQL. Применённые миграции не редактировать, добавлять новый файл.
- `scripts/` — продюсер, миграции, smoke.
- `test/unit/` — валидация, конфиг, retry, поведение consumer на подставном канале.
- `test/integration/` — настоящая PostgreSQL: начисления, отмены, гонки, лидерборд, HTTP.

SQL — в репозитории, бизнес-правила — в сервисе. Не добавлять generic-репозитории, дополнительные слои, CQRS и новые хранилища без конкретного требования.

## Инварианты

1. Деньги и очки — десятичные строки и `NUMERIC`; арифметика выполняется в SQL, JS `number` для денег не используется.
2. Ставка и счёт игрока меняются в одной транзакции. Счёт меняется атомарной дельтой (`points = points + $1`), а не через чтение и запись в JS.
3. ACK — только после commit или no-op. Auto-ack не включать.
4. Отмена списывает сохранённое `bets.points`, а не пересчёт по текущему курсу или полям события.
5. Отмена окончательна: поздний settled после отмены ничего не начисляет.
6. Владелец ставки проверяется до no-op; чужой `playerId` — конфликт.
7. Повторяются только временные ошибки БД (`isTransientDbError`); ошибки данных сразу уходят в DLQ.
8. Топ и позиция игрока считаются одним SQL-запросом. Порядок: очки DESC, `player_id` ASC (collation C), нулевые счета исключены.
9. Записи `bets` не удалять: на них держится идемпотентность.

## Проверки

```sh
npm run check                                  # prettier, eslint, build, unit
docker compose up -d --wait postgres rabbitmq
npm run test:integration
docker compose up --build -d --wait app
npm run test:smoke
```

Нужен `.env` из `.env.example`. Тесты запускаются из `dist`, поэтому после изменений нужна сборка. Integration работает только с базой, имя которой оканчивается на `_test`, во временной схеме. При изменении `BetsService`, `BetsRepository`, SQL или миграций запускать integration; при изменении consumer, `main.ts` или Compose — ещё и smoke. Блокировки не подменять моками и не ослаблять тесты ради зелёного прогона.

Особенность Nest: для `@EventPattern` нужна форма `@EventPattern<string>(...)`, иначе strict-сборка не проходит из-за перегрузки декоратора.

Не коммитить `.env`, `node_modules`, `dist`.
